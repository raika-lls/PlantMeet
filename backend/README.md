# PlantMeet Cloud API

Сервер: https://plantmeet-api.plantmeet-raika.workers.dev
Сайт: https://raika-lls.github.io/PlantMeet/

Общая база Cloudflare D1 подключена к GitHub Pages через HTTPS API. Конференции, аудитория встречи (группа/подгруппа), преподаватель и статус общие для устройств. Список обновляется каждые 5 секунд. Студент не может создавать или изменять конференции; изменение доступно автору.

## Вход

Демо-ИИН: 12 тестовых цифр, пароль минимум 8 символов. При первом входе создаётся демоаккаунт. Для того же кабинета на другом устройстве используйте одинаковые ИИН, пароль и роль. У разных студентов должны быть разные тестовые ИИН. Пароль хранится как PBKDF2-SHA256 хеш со случайной солью; ИИН хранится в виде хеша, токены сессий также хешируются. Одновременные сессии действуют 7 дней. Роль в демоверсии выбирается самостоятельно, без подтверждения статуса преподавателя. Настоящие персональные данные не требуются.

## Сохранение

- Конференции и аккаунты: таблицы D1.
- События, задания с получателями и оценки: серверные документы account_state, разделы teaching/grades, отдельно для каждого преподавателя. Ученику выдаются только адресованные ему задания и оценки. Нормализованные таблицы миграции 0003 подготовлены для дальнейшего развития; текущий UI сохраняет эти разделы документами.
- Посещения студентов: visits; при завершении занятия неявки зарегистрированным студентам соответствующей группы заносятся в absences. Преподаватель в посещаемость не включается.
- Старые данные браузера преподавателя переносятся при первом входе, если на сервере ещё нет раздела.
- Видео по выбору владельца пока остаются в IndexedDB браузера. R2 не включен, видео не загружается в Cloudflare. Просмотр и удаление доступны владельцу на этом браузере, хранение один календарный месяц.
- Изменения без ответа сервера не объявляются успешно сохранёнными; показывается сообщение об ошибке.

Встречи открываются через Jitsi; сервер выдаёт всем участникам одно имя комнаты. Вход преподавателя в Jitsi может требоваться отдельно. Полноценный звонок с двумя физическими устройствами нужно проверить отдельно.

## Обслуживание

Из корня репозитория (или скорректировать пути):
`npx wrangler d1 migrations apply plantmeet --remote --config backend/wrangler.json`
`npx wrangler deploy --config backend/wrangler.json`

Тесты: Node.js 24+, `node --test backend/tests.mjs backend/storage-tests.mjs`. Проверяются идентичности, две сессии одного аккаунта, права, группы, совместное расписание, сохранение документов, посещаемость и SQLite-ограничения.

Файл wrangler.json содержит только идентификаторы ресурсов, не секреты. Пароли, токены и OAuth-данные в Git не добавляются.
